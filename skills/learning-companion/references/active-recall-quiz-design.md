# Active Recall Quiz Design (Stage 3)

3–5문항을 출제한다. 일괄 출제 금지 — 1문항씩 사용자 답을 받고 적응적으로 다음을 만든다.

## 출제 분포

| Bloom 단계 | 문항 수 | 예시 |
|---|---|---|
| Remember (사실 재생) | 0–1개 | "Agent의 정의는?" |
| Understand (의미 파악) | 1–2개 | "Workflow와 Agent의 결정 시점 차이는?" |
| Apply (적용) | 1–2개 | "이 상황은 Workflow인가 Agent인가? 왜?" |
| Analyze (분해/비교) | 0–1개 | "Reflection 패턴이 없으면 Agent라 부를 수 있을까?" |

Remember에 치우치면 단순 암기. Apply/Analyze에 치우치면 인지 부하 과다. **Understand + Apply가 중심**.

## 좋은 문항의 4조건

1. **원문에 근거 있음**: 정답을 자료에서 인용할 수 있어야 한다
2. **단답 가능**: 100자 이내로 답할 수 있는 형태
3. **함정 명확**: 자주 헷갈리는 변별점을 노린다
4. **다음 문항의 입력**: 정답이든 오답이든, 다음 문항이 그 응답에 적응한다

## 채점 트레이스

각 답변에 대해 다음 4가지를 응답으로 준다:

1. ✅/❌
2. 정답 (간결)
3. **원문 인용**으로 근거
4. (오답일 때) 어디서 갈렸는지 짚어주기 — Stage 4로의 자연스러운 다리

## 오답 → Metacognition 전이

오답이 발생하면 채점 직후에 묻는다: **"왜 그렇게 답하셨어요? 이 부분을 더 짚어볼까요?"**

사용자가 "더 짚어볼까요"에 동의하면 → `references/metacognition-prompts.md` 진입.

## 사용자 옵션

- "더 어렵게": Apply/Analyze 비중 증가
- "쉽게": Remember/Understand 위주
- "퀴즈만 할래": Stage 3만 수행, 노트 status는 `partial`

## 안티패턴

| 안티패턴 | 이유 |
|---|---|
| 5문항 한꺼번에 던지기 | 적응 못 함, 인지부하 |
| 객관식만 출제 | Recall 효과 약함 |
| 너무 일반적 ("이 글의 요지는?") | 근거 모호, 채점 불가 |
| 원문 밖 지식 요구 | 학습 단계가 아니라 시험 |
